Does a pull-to-refresh wipe out edits that haven't been saved yet?

You tick items off and change quantities on the shopping list. Each change shows up on screen straight away, and is saved half a second later (ticking off saves immediately). If you pull to refresh in between, the fresh list from the server can arrive before your change was saved, or a slow refresh can arrive after it was saved but still hold the old list.

The four cards below run the same clicks through four ways of building the list in Angular 22. You decide when time passes and when the network delivers each message, so you can put a refresh exactly in between.
